도구 블록(OMC, oh-my-codex)과 어긋나면 이 지침을 따른다. 도구 블록이 「묻지 말고 끝까지」 라고 해도 사용자가 정할 결정은 묻는다.

## 사용자

백엔드 개발자, 한국 Java 방식에 익숙, Python 경험 적음.

- 응답과 문서는 자연스러운 한국어로 쓴다.
- 머신러닝 용어는 Java·백엔드 개념에 빗대고, Python 은 Java 와 다른 문법만 짚는다.
- 수학보다 속도, 메모리, 정확도, 배포 영향을 먼저 말한다.
- 처음 보는 결정은 배경과 권장 이유를 붙여 묻는다.
- 번호는 원 문자(①) 대신 `**1.**` 이나 목록 번호로 쓴다.
- 대화 응답에서 업무(두레이 업무, PR)를 가리킬 때는 번호와 제목을 함께 쓴다(사용자 결정).
  - 예: 「361 스케줄러 정기 작업 실행 기록」. 번호만으로는 무슨 일인지 떠올리지 못한다.
- 사용자에게 하는 설명과 질문은 처음 듣는 사람도 한 번에 알아듣는 말로 쓴다(사용자 결정).
  - 무엇을 고치는지와, 그래서 무엇이 어떻게 달라지는지를 함께 말한다.
  - 내가 문서나 코드에서만 쓰던 낱말은 평소 쓰는 말로 바꾼다. 예: 판정 → 결과, dispatch → worker 에게 맡긴 일, 머리 주석 → 파일 맨 위 설명
  - 내부 식별자(UUID 나 그 앞자리, 커밋 해시, 실행 ID)로 대상을 부르지 않는다. 대화, 업무, 위키, 보드처럼 사람이 읽는 곳 모두 그렇다(사용자 결정). 예: 「01a1e8ad 평가」 → 「오늘 정한 판단 규칙을 넣은 지시문 묶음 초안의 dev 평가」. 식별자는 worker 지시와 명령 인자에만 쓴다
  - 개발자가 영어나 음차로 말하는 용어(컴포넌트, upstream, 캐시)는 바꾸지 않는다. 어느 쪽인지 정하는 기준은 korean-check 의 「용어를 옮기지 않는다」 가 갖는다(사용자 결정).
  - 예: 「CI 결과로 확인을 대체한다」 → 「완료 확인 규칙을 고친다. CI 가 같은 커밋에서 이미 통과한 테스트는 다시 돌리지 않아서 기다리는 시간이 준다」
- 미완료 작업의 **남은 작업** 목록(상태와 다음 단계)은 큰 단위 작업이 끝났을 때 한 번 적는다. 응답마다 되풀이하지 않는다(사용자 결정).

## 작업 방식

- 커밋은 관심사별로 나눈다.
- 기능 작업은 spec → technical-design → plan → implementation → verify → docs-consolidate 순서로 진행한다.
  - spec 은 사용자와 깊게 인터뷰해 결정을 닫고 확인받는다. 확인받은 스펙 없이 구현 worker 를 띄우지 않는다.
  - 단계별 진입·완료 조건은 `~/personal/fos-skills/skills/spec/references/feature-docs.md` 의 「인계」, 단계 조율은 `~/personal/fos-skills/skills/orch/references/feature-loop.md` 가 갖는다.
  - 오타·문서 정정 같은 작은 고침은 예외로 하고, 예외로 둔 이유를 알린다.
- 컨텍스트가 찼다는 경고(compact 권고 등)는 사용자에게 알리지 않고 자동 압축을 믿는다. 경고 때문에 작업을 줄이거나 멈추지 않는다(사용자 결정 2026-11-16).
- 저장소 관례보다 나은 패턴이 있으면 제안하고 적용한다.
- 수십 초 넘게 걸리는 명령(테스트, 빌드, CI 조회)은 백그라운드로 돌려 대화를 막지 않는다.
- 현재 세션이 연 저장소가 아닌 곳을 고치고 커밋하는 일은 `orch` 로 worker 에게 맡긴다.
- 사용자가 정한 규칙은 OMC memory·notepad 가 아니라 문서에 둔다.
  - 모든 저장소에 적용하면 이 파일에 둔다.
  - 한 저장소에만 적용하면 그 저장소의 지침이나 `.claude/<스킬>-overlay.md`(orch 는 `.orch/overlay.md`)에 둔다.
  - 상세 절차는 스킬에 둔다.

## 파일 자리

- 한 번 쓰고 끝나는 파일은 세션 임시 폴더(scratchpad, 없으면 `$TMPDIR`)에 둔다. 저장소의 `.orch/`, `.omc/` 에 쌓지 않는다. worker 에게도 그렇게 시킨다.
  - 조사 스크립트와 결과, PR 본문·커밋 메시지 초안이 여기 해당한다.
- 작업 폴더에는 되풀이해 쓰는 도구만 둔다.
- 사용자가 볼 미리보기 HTML 은 그 저장소의 `.omc/previews/` 에 두고 시스템 기본 브라우저로 띄운다.
  - 이미 띄운 미리보기를 고친 뒤에는 `preview-refresh <파일>` 로 열린 탭을 새로 고친다. 열린 탭이 없을 때만 새로 연다(사용자 결정).
- 새 스크립트는 sh 대신 TypeScript 나 Python 으로 쓴다(그 저장소나 스킬이 쓰는 쪽). 반복 실행하는 코드와 heredoc 은 `scripts/` 로 뺀다.

## 문서

- 에이전트가 읽는 지침과 참조 문서는 핵심만 짧게 쓴다. 에이전트가 방향을 잡을 만큼만 적고, 사람도 읽고 이해할 수 있게 쓴다(사용자 결정).
- GitHub PR 은 한국어가 기본이다.
- 원본이 바뀌면 함께 낡는 개수(도메인 수, 명령 수, 「다음 세 가지」)를 문서와 테스트에 적지 않는다.
  - 원본을 가리키고, 테스트는 형식과 동작을 본다.
  - 동작 규칙의 값(최대 1000건)과 실측 기록(표본 12개)은 둔다.
- 업무 글과 사람에게 보내는 메시지(Dooray 업무·댓글, 메신저, 메일, 사내 회신)는 쓰기 전에 `~/.claude/references/work-writing-persona.md` 를 읽는다. 호칭 규칙도 그 문서가 갖는다.
- 사람에게 보내는 메시지는 끝에 「🤖 이 메시지는 AI가 작성했고, 작성자가 검토했습니다.」 를 단다(사용자 결정).
  - 받는 사람이 AI 작성을 모른 채 읽어 불쾌하지 않게 하려는 것이다.
- 두레이 메신저 본문에 쓸 수 있는 형식은 `~/personal/fos-skills/export-only-skills/content-preview/references/messenger-rendering.md` 가 갖는다(사용자 결정).
- mermaid 다이어그램은 손그림과 색을 쓴다. 머리에 `config: look: handDrawn` 을 두고 `classDef` 로 노드 종류마다 색을 입힌다(사용자 결정).
  - 두레이 위키·업무에는 이미지로 바꾸지 않고 mermaid 코드 블록으로 쓴다. 이미지는 고치기 어렵고 어색해 보인다(사용자 결정).
- 비공개 지식을 공개 맥락에 내지 않는다.

## 스킬

- 스킬을 만들거나 구조를 바꾸면 `skill-creator` 를 쓰고, 쓰기 전에 `~/.claude/references/skill-structure.md` 를 읽는다. 공용 스킬은 `~/.claude/references/skill-sync.md` 도 읽는다.
- 스킬의 일반 동작을 고칠 일이면 저장소 오버레이로 덮지 않고 스킬 자체를 고친다(사용자 결정).
  - 오버레이에는 그 저장소에만 맞는 값(프로젝트, 태그, 상위 업무 목록, 연동 여부)만 둔다.
- 실행 중 지시대로 안 된 곳, 우회한 곳, 사람에게 물어야 했던 판단, 스크립트로 바꿀 수 있는 산문을 메모했다가 끝나고 개선 후보로 알린다.
  - 셋을 모두 만족할 때만 올린다. 다음 작업의 시간이나 실패가 실제로 준다. 오타·일시 장애 같은 단순 함정이 아니다. 스크립트·검사기·구조로 막을 수 있다(「주의한다」 로만 막히면 올리지 않는다).
  - 기준마다 근거(파일과 줄, 로그, 실측)를 붙인 표로 올린다. 근거를 대지 못하거나 원인을 확인하지 못한 후보는 보류로 올린다(사용자 결정).

## 브라우저

- 개인 서비스(`*.fosworld.co.kr`, 개인 Google 계정 사이트)는 `BROWSER_EGO_PURPOSE=personal` 로 연다.
- ego 브라우저는 에이전트가 조작하거나 읽을 때만 쓴다.

## zsh 함정

- `timeout`, `gtimeout` 이 없다. 도구 자체의 제한 시간 옵션이나 백그라운드 실행을 쓴다.
- 변수 이름에 `path`, `fpath`, `cdpath`, `manpath` 를 쓰지 않는다. `PATH` 류와 묶여 명령을 못 찾게 된다(`for`, `while read`, `local` 포함).
- 변수 뒤에 `:` 을 바로 붙이지 않는다. `$b:src` 는 오류, `$b:t` 는 값이 바뀐다. `${b}:src` 로 쓴다.
- `=` 로 시작하는 낱말은 따옴표로 감싼다. `echo ======` 는 명령 경로 치환으로 실패한다.
- 파일에 쓰는 리다이렉트(`>`, `>>`)가 있는 Bash 명령은 처음부터 `set +o noclobber;` 로 시작한다(사용자 결정).
  - 빠지면 개인 훅(`bash-clobber-guard.py`)이 붙여 넣고, 바뀐 입력을 자동 모드가 한 번 거부한다.
