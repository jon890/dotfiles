# 스킬 층과 동기화

스킬을 고치기 전에 어느 층을 고쳐야 하는지 정한다.
엉뚱한 층을 고치면 다음 내보내기에 덮이거나, 고쳐도 내 환경에 반영되지 않는다.

## 세 층

| 층 | 위치 | 무엇을 두나 |
| --- | --- | --- |
| 저장소 로컬 | `<repo>/.claude/skills/` | 그 저장소에서만 뜻이 통하는 스킬 |
| 개인 공용 | `~/personal/fos-skills/` | 회사와 개인 작업에서 함께 쓰는 스킬 |
| 팀 공용 | `~/projects/AiSdtSkill/skills/` | 사내 업무용이고 팀원도 쓰는 스킬 |

실행되는 것은 `~/.claude/skills/<이름>` 심링크가 가리키는 층이다.
전역 스킬이 저장소 스킬보다 우선하므로, 같은 이름이 겹치면 저장소 쪽이 가려진다.

```bash
cd ~/.claude/skills && for n in *; do printf '%-24s %s\n' "$n" "$(readlink "$n" || echo '(실체)')"; done
```

## 개인 공용과 팀 공용의 관계

**`fos-skills` 가 원본이고 `AiSdtSkill` 의 것은 사본이다.**
팀원이 저장소를 둘 받지 않아도 되게 사본을 두고, 어긋남은 스크립트가 잡는다.

대상은 다섯이다. `content-preview`, `planning`, `build-with-teams`, `docs-check`, `review-fix`.
목록의 단일 소스는 `fos-skills/scripts/export-to-team.sh` 의 `SHARED_SKILLS` 다.

```bash
cd ~/personal/fos-skills
./scripts/export-to-team.sh            # 어긋난 파일만 낸다. 어긋나면 종료 코드 1
./scripts/export-to-team.sh --apply    # 원본 내용을 팀 저장소로 복사한다
```

- 방향은 개인 공용에서 팀 공용으로 한쪽이다. 반대 방향 명령은 없다.
- 내보낸 뒤 팀 저장소에서 따로 커밋해야 팀에 전파된다.
- 두 저장소의 frontmatter 규약이 달라 스크립트가 변환한다.
  원본은 `metadata.version`, 팀 저장소는 최상위 `version` 이다.
- `references/work-writing-persona.md` 는 개인 자산이라 내보내지 않는다.

다섯 밖의 스킬은 한쪽에만 있으므로 그 저장소에서 직접 고친다.
`weekly-report`, `create-pr`, `dooray-task`, `nbrain` 처럼 사내 업무 전용은 팀 저장소가 소유하고,
`pr-review`, `presentation`, `harness-cleanup` 은 개인 공용이 소유한다.

## 고치기 전에 확인하는 것

1. 그 스킬이 다섯 안에 있는지 본다. 있으면 **원본을 고친다.**
2. 심링크가 어디를 가리키는지 본다. 사본을 가리키면 내보내기 전까지 내 환경에 반영되지 않는다.
3. 버전을 올린다. 판단 기준은 `fos-skills/README.md` 의 「버전과 변경 이력」 이다.
4. 내보내고, 두 저장소에서 각각 커밋한다.

## 실측 함정

| 함정 | 무엇이 일어났나 |
| --- | --- |
| 팀 저장소를 직접 고쳤다 | 다음 `--apply` 가 그 수정을 조용히 덮는다. 스크립트 머리말이 이것을 경고한다 |
| 원본만 고치고 내보내지 않았다 | 심링크가 사본을 가리켜 고친 내용이 실행되지 않았다. 이미 고친 함정이 살아 있었다 |
| 같은 번호에 다른 내용이 둘 생겼다 | 방향 보호는 팀 버전이 더 **높을** 때만 막는다. 같으면 통과하고 덮는다 |

세 번째를 피하려면, 팀 쪽을 먼저 건드렸다는 것을 알아차린 시점에
원본의 버전보다 한 단 위로 올려 내보낸다. 같은 번호를 재사용하지 않는다.

## 층을 올릴 때

저장소 로컬에서 개인 공용으로, 개인 공용에서 팀 공용으로 올린다.
올리는 시점은 여러 저장소에서 쓸 만하다고 확인됐을 때, 그리고 팀원도 쓸 만할 때다.

옮길 때 심링크를 다시 걸고, 커밋은 옮기는 시점에 한 번만 남긴다.
개인 공용에서 팀 공용으로 올리는 것은 이동이 아니라 사본 추가다.
`SHARED_SKILLS` 에 이름을 더하고 내보내면 그때부터 원본과 사본 관계가 된다.
