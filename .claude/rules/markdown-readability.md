# 마크다운 가독성과 작성 함정

문서 구조는 정보량에 맞추고 같은 내용을 반복하지 않는다.
다이어그램은 관계가 글보다 분명해질 때만 사용하며, 외부 게시 대상이 지원하면 Mermaid를 우선한다.

## 작성 규칙

- 한 문장이나 의미 단위마다 줄을 나눈다.
- 한 단락이나 목록에 항목이 셋 이상이면 하위 목록으로 분리한다.
- 한 단락이 여러 주제를 담으면 제목, 목록, 표 중 가장 작은 구조로 나눈다.
- 표 셀에 정보가 많으면 `<br>`로 분리한다.
- 본문에서 `A + B`, `A · B`, `A & B`처럼 항목을 이어 붙이지 않는다.
- 자동 번호를 붙이는 문서에서는 제목에 번호 접두사를 넣지 않는다.
- 평문 문장은 동사로 끝낸다. 제목, 표, 목록 항목은 명사구로 끝내도 된다.
- 번호 목록 중간에 항목을 추가하면 소수 번호를 만들지 말고 뒤 항목을 다시 매긴다.

## 렌더링 함정

| 패턴 | 문제 | 대응 |
| --- | --- | --- |
| 범위 표기의 `~` | 같은 단락의 물결표가 취소선으로 해석될 수 있음 | `부터`, `까지`, `-` 또는 `\~` 사용 |
| `§` | 한국어 문서에서 의미를 바로 알기 어려움 | `섹션`, `장` 또는 번호 사용 |
| quoted heredoc 안의 불필요한 escape | 역슬래시가 본문에 그대로 남음 | 본문 파일을 만들고 `--body-file`로 전달 |

## 내용 점검

- 표와 본문, 요약에서 같은 사실을 반복하지 않는다.
- 독자가 판단하거나 행동하는 데 필요하지 않은 내부 세부는 뺀다.
- 정보보다 제목과 강조가 많으면 구조를 줄인다.
- 공허한 수식 대신 사실을 쓰거나 문장을 삭제한다.
