# 한국어 표현 정책

사용자 응답과 문서는 한국 개발자가 한 번에 이해할 수 있는 자연스러운 한국어로 작성한다.
코드 식별자, 명령어, 경로처럼 원문이 정확해야 하는 문자열은 번역하지 않는다.

## 문장 구성

- 조사와 어미를 생략하지 않는다. 명사만 이어 붙여 독자가 관계를 짐작하게 만들지 않는다.
- 평문은 서술어와 종결어미로 끝낸다. 제목, 표, 목록 항목은 명사구로 끝내도 된다.
- 한 산출물 안에서 공손체와 평서체를 섞지 않는다.
어느 쪽으로 갈지 먼저 정하고 끝까지 지킨다. 제목과 표, 목록 항목은 이 판단에서 제외한다.
- 문맥에서 복원할 수 없는 주어와 목적어는 생략하지 않는다.
- 서술의 대상을 적는다. `크게 작용한다` 는 무엇에 작용하는지가 없다.
- 지시어가 가리키는 것을 앞에 둔다. `그 경계` 가 무엇인지 앞 문장에 없으면 이름을 쓴다.
- `의`를 한 구에 두 번 겹치지 않는다. 겹친다는 것은 성분이 빠졌다는 신호다.
- 비유어로 일반 명사와 동사를 대체하지 않는다. 해당 분야에서 굳은 관용 표현은 그대로 쓴다.
- 엠대시로 절과 절을 잇지 않는다. 콜론이나 접속사로 바꾼다. 목록과 표에서 이름과 설명을 가르는 용도는 그대로 쓴다.


| 고칠 문장                           | 빠진 것   | 고친 문장                            |
| ------------------------------- | ------ | -------------------------------- |
| 그러면 경고가 붙습니다.                   | 대상과 상황 | 이미 작업 중인 파일에도 경고 표시가 붙는다.        |
| 지출 비용 추론 용도의 토큰 카운트 함수의 오류 상황에서 | 조사와 어미 | 지출한 비용을 추론하는 토큰 카운트 함수에 오류가 발생하면 |
| 컨텍스트 압축 전 신중 반영한다.              | 서술 관계  | 컨텍스트가 압축되기 전에 신중하게 반영한다.         |
| 코드로 박는 자리                       | 비유어    | 코드에 명시하는 위치                      |


### 출력 직전 점검

검사기가 잡지 못하는 축이다. `종료 코드 0` 은 이 축을 통과했다는 뜻이 아니다.

내보내기 직전에 여섯을 본다.

1. **비유를 쓴 자리가 있는가.** 묻힌다, 뒤집힌다, 조용히, 함정, 덮는다, 새어 나간다.
 저장소 밖으로 나가는 글이면 실제 동작이나 수치로 바꾼다
2. **문서 번호로 가리킨 자리가 있는가.** ADR, PR, 이슈 번호를 적고 넘어갔으면
 읽는 사람이 그 문서를 열 수 없다
3. **내가 지어낸 이름이 있는가.** 제품, 도구, 지표를 부를 때 그 조직이 실제로 쓰는
 표기를 찾아 쓴다. 없으면 묻는다
4. **제목과 표 머리가 질문형인가.** `무엇을 바꿨나`, `어떻게 재는가` 는 제목이 아니다.
 `변경점`, `측정 방법` 처럼 명사구로 쓴다
5. **표가 이미 말하는 것을 문장으로 다시 썼는가.** 표 아래 문장은 표에 없는 것만 적는다.
 `이번에 바꾼 것은 하나다` 는 표의 마지막 열이 이미 말한다
6. **지우면 손해가 없는 절이 있는가.** 다른 곳이 이미 말하는 것, 링크 없는 관련 목록,
 본문이 곧 말할 것을 앞에서 미리 말하는 요약이 여기 해당한다

1번과 2번은 `writing-structure.md` 의 독자 구간이 정한다. 저장소 안 문서는 해당하지 않는다.

### 고쳐 쓴 예시

실제로 지적받아 고친 것이다. 검사기가 잡지 못해 여기 둔다.
부분 문자열로 걸면 `증가`, `추가`, `평가` 까지 잡혀 금지어 목록으로 만들 수 없다.

**제목과 표 머리**

| 쓰지 않음 | 씀 |
| --- | --- |
| 무엇을 바꿨나 | 변경점 |
| 무엇이 달라졌나 | 결과 |
| 무엇이 정하나 | 설정 |
| 어떻게 재는가 | 측정 방법 |
| 정답지와 글자가 얼마나 같은가 | 글자 점수 |

**비유를 수치나 동작으로**

| 쓰지 않음 | 씀 |
| --- | --- |
| 262.6초가 그 안에 묻힌다 | 단계 합계 2084.4초의 12.6% 다 |
| 표 분석과 OCR 이 시간을 지배한다 | 표 분석 934.7초와 OCR 610.5초가 전체의 대부분이다 |
| 다른 호출에 밀린다 | 다른 사용자의 호출에 영향을 받는다 |
| 판정할 때 빠지기 쉬운 함정 | 판정할 때 유의할 점 |
| 읽어 가는 곳이 없다 | 아무 데도 쓰이지 않고 버려진다 |
| 조용히 틀린다 | 오류가 드러나지 않는다 |
| 워커를 늘릴 때 그 여유가 돌아온다 | (앞 문장이 CPU 와 메모리를 덜 쓴다고 이미 말하므로 지운다) |
| 로그를 파일에 잇는다 | 로그를 파일에 연결한다 |
| 단계가 겹쳐 돈다 | 단계가 병렬로 수행된다 |

**번역투**

| 쓰지 않음 | 씀 |
| --- | --- |
| 바꾼 설정은 `X` 다. `A` 에서 `B` 로 내렸다 | `X` 설정을 `A` 에서 `B` 로 변경했다 |
| 판정 근거는 ADR-053 이 소유한다 | (밖으로 나가는 글에서는 내용을 본문에 쓴다) |

**지어낸 이름**

| 쓰지 않음 | 씀 |
| --- | --- |
| 문서 변환기, 파서 | Document Parser |
| 그림 | 이미지 |
| 정점 비트맵 | 줄이기 전 이미지 |
| 공통 부분 수열 비율 | 순서를 지킨 채 겹치는 글자의 비율 |

새로 고친 것이 생기면 이 표에 한 줄을 더한다.

## 문장을 늘어놓는 방식

- 한 문장이나 의미 단위마다 줄을 나눈다. 한 줄에 한 호흡만 담는다.
- 본문에서 `A + B`, `A · B`, `A & B`처럼 항목을 이어 붙이지 않는다. 쉼표나 `와/과`, 목록을 쓴다.
- `=` 나 `→` 로 동치와 인과를 압축하는 것은 한 단락에 한 번까지다. 반복되면 표로 바꾼다.

## 용어를 옮기지 않는다

새 번역어를 만들지 않는다. 옮기기 전에 그 저장소가 이미 쓰는 표기를 찾아 그것을 따른다.

```bash
grep -rn "<후보 표기>" docs/ CLAUDE.md
```

기존 표기가 없을 때만 판단한다.

- 코드 식별자, 명령, 경로, 라이브러리 이름은 옮기지 않는다.
- `backend`, `version`, `pipeline`, `rate limit`, `backpressure`, `latency` 처럼
한국 개발자가 영문으로 읽고 말하는 용어는 옮기지 않는다.
- 직역한 한자어를 새로 만들지 않는다. 무엇이 어떻게 됐는지 쓴다.
- 남은 것만 쉬운 말이나 실제 동작으로 풀어 쓴다.

실측으로 되돌린 사례다. 아래 표는 검사기가 읽지 않는다. 금지어 목록은 위 매핑 표 하나뿐이다.


| 옮긴 말   | 원어          | 저장소가 쓰던 표기 |
| ------ | ----------- | ---------- |
| 판      | version     | 버전         |
| 정점     | peak        | 피크         |
| 글자 추출기 | PDF backend | 파싱 백엔드     |
| 절단     | truncation  | 뒷부분 누락     |


`판` 과 `정점` 은 금지어로 등록할 수 없다.
검사기가 부분 문자열로 찾아 `판단`·`판정` 과 `그래프의 정점`·`수정점검` 까지 걸린다.
