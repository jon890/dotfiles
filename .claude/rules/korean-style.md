# 한국어 표현 정책

사용자 응답과 문서는 한국 개발자가 한 번에 이해할 수 있는 자연스러운 한국어로 작성한다.
코드 식별자, 명령어, 경로처럼 원문이 정확해야 하는 문자열은 번역하지 않는다.

## 외래어 매핑 표

이 표는 `~/.claude/scripts/korean-style-check.sh`가 읽는 단일 소스다.

| 금지 | 권장 |
| --- | --- |
| 매트릭스 (matrix) | 표, 영향 표, 변경 표 |
| 트리아지 (triage) | 분류, 분류 작업 |
| 베이스라인 / baseline | 기준값, 기준점, 기준선 |
| 스파이크 (spike) | 사전 조사, 탐색 작업, 실증 |
| 게이트 (gate) | 점검, 사전 점검, 통과 조건 |
| wall-time / wall clock time | 전체 처리 시간, 실제 처리 시간 |
| silent failure | 묻혀버린 실패, 노출 안 되는 실패 |
| in-flight (요청) | 처리 중인 요청, 진행 중인 요청 |
| 리포지토리 위생 (repo hygiene) | 리포지토리 정리, gitignore 정비 |

| 패턴 답습 | 동일 패턴 적용, 그대로 적용 |

## 작성 원칙

- 표에 없는 생소한 외래어, 한자어, 비유어도 쉬운 말이나 실제 동작으로 풀어 쓴다.
- `rate limit`, `pipeline`, `backpressure`처럼 한국 개발자가 영문에 더 익숙한 용어는 그대로 둔다.
- 기술 문서의 `Latency`, `Throughput`, `Saturation`은 처음 한 번만 한국어를 병기한다.
- 평문 문장은 동사로 끝낸다. 제목, 표, 목록 항목은 명사구로 끝내도 된다.
- 작업 범위 밖의 기존 문체는 함께 고치지 않는다.
